# KinMeet mobile

React Native app for KinMeet. iOS is the first release target. The same Expo project includes an Android package so a later Android release does not need a new app.

Repository overview and local API setup live in the [root README](../README.md). The screen map is in [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## Stack

Expo SDK 58, React Native, TypeScript, React Navigation, NativeWind (Tailwind), Axios, expo-secure-store, Socket.io client, Jest, React Native Testing Library.

`android/` and `ios/` are generated by Expo prebuild or EAS and are not committed.

## Scripts

| Command | Description |
| --- | --- |
| `npm start` | Expo dev server. Scan the QR code with a physical iPhone |
| `npm run ios` | Open the app on the iOS Simulator (macOS with Xcode) |
| `npm run android` | Open the app on Android |
| `npm test` | Jest, single run |
| `npm run test:watch` | Jest watch mode |
| `npm run typecheck` | `tsc --noEmit` |

## Environment

Copy [`.env.example`](./.env.example) to `mobile/.env`:

```env
EXPO_PUBLIC_API_URL=http://localhost:8080/api
```

A physical iPhone cannot use `localhost`. Set `EXPO_PUBLIC_API_URL` to your Mac's LAN address, for example `http://192.168.1.20:8080/api`. The iOS Simulator can keep `localhost`. The Android emulator uses `http://10.0.2.2:8080/api`. Native HTTP clients are not limited by the API's browser CORS list.

## Run on an iPhone

1. Install [Expo Go](https://apps.apple.com/app/expo-go/id982107779) from the App Store. It matches this project's SDK 58.
2. Create a free Expo account. From `mobile/`, run `npx expo login`. In Expo Go, tap the account icon and sign in to the same account. A physical iPhone will not open the project until both are signed in.
3. Put the Mac and the iPhone on the same Wi-Fi. In `mobile/.env`, set `EXPO_PUBLIC_API_URL` to the Mac's LAN address.
4. Start the API, then from `mobile/` run `npm start` and scan the QR code with the iPhone Camera.

`npm run ios` opens the Simulator and is the wrong command for a phone.

## Layout

- `src/screens/` — screens grouped like the web app. Login and the signed-in profile call the API; other screens are placeholders
- `src/navigation/` — auth stack, tabs, chat, profile, and settings
- `src/components/common/` — shared screen chrome
- `src/contexts/` — auth session
- `src/services/` — API client (`authAPI`, `profileAPI.getProfile`) and a socket client that does not connect on launch
- `src/types/`, `src/constants/`, `src/utils/`

Admin stays on the web app.
